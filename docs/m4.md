# M4: Codex CLI adapter (partial)

Target: Codex 0.163.0 shared app-server. Linux ARM64 live evidence is in
[the M4 lab](../research/lab/results/m4-codex/README.md). M4 is not fully accepted:
stock native read-only fork feasibility is proven, but hardened product ask is
unavailable until authority isolation and enforceable budget accounting exist.
Local checks and review are recorded in [M4 verification](m4-checks.md).

## Current operation

The [local marketplace/plugin](../adapters/codex/README.md) provides a skill and
`UserPromptSubmit` hook. Copy the trusted executable into `plugin/bin/peerturn`
before enabling the plugin and accepting the actual hook trust UI. The helper
is within the plugin content and has a pinned relative path. Review updated
packages before use; the lab did not observe automatic trust-dialog invalidation
after a bundled binary replacement/resume. No such guarantee is claimed.
The [preview installer](install.md) verifies signed archives; automatic reload
is not claimed. Arbitrary `-c` overrides
and `--dangerously-bypass-hook-trust` may select embedded mode in this build;
use normal shared-daemon configuration. Embedded/`--no-daemon` is unsupported.

From a tool child in the selected TUI:

```sh
peerturn init --codex-current --relay https://relay.example --file-permissions
peerturn daemon start
```

Run the foreground daemon under a normal local supervisor or separate terminal.
The initialization reads `CODEX_THREAD_ID`, checks that UUID with
`thread/loaded/list` and metadata-only `thread/read` on the same private shared
socket, and persists its binding before issuing grants. Unloaded/embedded threads
cannot bind (`needs_rebind`); stale bindings cannot attach a neighbor. A new
native binding needs a new explicit identity, not promotion of an old preview.
Separate sessions require explicit separate state/config/runtime profiles because
the current daemon still serves one local identity per instance. A shared cwd
does not select a session.

Create `peerturn invite create --current --scope coauthor`. If a session-bound
MCP entry is active, the receiving agent passes the full owner-pasted invitation
to `peer_join(text)`; the daemon parses it without an invitation in argv or a
plaintext file. The human terminal alternative is
`peerturn join --current --scope coauthor --link-stdin` with interactive stdin.
The current tool UUID replaces a missing `--session` flag; an explicit different
UUID is rejected. Conflicting Claude/Codex current-session environments fail
with `binding_mismatch`. Invitation/join/hello
reuse M2.5's directional encrypted grant handshake. CLI/MCP can inspect attached
peers, inbox and receipts; the skill sends via CLI. MCP exposes seven tools,
including `peer_join` and a coauthor-only send schema. Native MCP leases carry
the verified tool thread. Configure the verified binary as `mcp --current` only
where the host supplies that native environment; plugin install alone does not
register MCP. Host-started environment inheritance remains unqualified; see
[MCP binding and limits](m25.md#mcp-proxy). Missing binding never falls back to
an automatically selected daemon session or shared cwd.

## Delivery and status

Coauthor is strong trust with normal receiving-agent capabilities. It is not a
sandbox, and peer text can influence later owner turns. No file expansion, URL
fetch, transcript attachment or discovery-based authority is added.

The daemon verifies the received packet and live grant, saves a delivery intent,
then submits one literal JSON-framed input via `thread/queue/add`. Its stable
`clientUserMessageId` is `peerturn:<message-id>`; the returned queue item ID is
kept only in local encrypted evidence. Queue admission records `adapter_accepted`,
never `model_input` or completion. Busy input waits for the next turn. No steer,
raw injection, fresh live exec or automatic resubmission is used.

An ambiguous queue result is `in_doubt`. Restart fences unresolved native intents
before processing new input. Observed native results and their signed receipt
outbox commit in one transaction; the precommitted immutable journal reservation
allows notification recovery without a new native submission. A crash before
an observed result is journaled still requires native reconciliation; no
exactly-once effects are promised. Native queue/turn IDs never enter peer receipts.

`peerturn delivery resolve MESSAGE_ID --sent` accepts the owner's assertion that
the exact ambiguous attempt was submitted; it does not prove model input or effects.
For Codex, `--not-sent` refuses with `in_doubt`: this adapter cannot establish that
an ambiguous native queue item was never started. Absence from `thread/queue/list`
or a transcript is insufficient, because the item may already have run. The item
stays fenced and is not re-enqueued. A locally proven never-authorized intent can
still recover automatically with a fresh attempt; it never called `queue/add`.

`--kind inform` stores without any queue/add or wake. The root-thread hook returns
only a fixed small notice (at most eight items, count and fingerprint labels,
below 512 bytes including JSON), directing the agent to `peer_inbox` or
`peerturn inbox --json`. Peer bodies never enter hook `additionalContext`, which
Codex records in developer role and may spill to plaintext temporary files.
Subagent inputs (`agent_id`/`agent_type`, even null), unknown schemas and canonical
PeerTurn coauthor frames do not consume FYI. Peer frames report a start separately.
Stock hooks do not inherit `CODEX_THREAD_ID`: their native stdin `session_id`
is checked against the exact stored binding. The API cannot establish general
owner provenance for arbitrary other integrations. Hook failure returns `{}`
without blocking the owner. Notice preparation changes no receipt. Only after
successful stdout write does the helper acknowledge the offer within its shared
two-second budget; `offered` means that write, not Codex/model ingestion. A lost
ACK may repeat a small notice. CLI/MCP acknowledge inbox bodies only after a
successful complete output write; that ACK records `delivered`, distinct from
model input or completion. A bounded batch commits stages and signed receipt
outbox atomically; a failed transaction cannot publish a false receipt on recovery.

`status` checks native binding and queue service; boundary delivery stays
unverified until the daemon observes the exact hook callback. It reports total
pending inform count, native UUID, receipt stages, onboarding failures and typed
unavailability. Owner revoke remains usable when the native thread is stale.
Use `peerturn grants` and `peerturn grants revoke GRANT_ID` for Codex revocation.
`session bind` and `session unbind` are Claude-only and return `unsupported` for
a Codex current session or binding; they do not disconnect a Codex native queue.
Revocation prevents new admission and attempts `thread/queue/delete` for every
retained queue item ID, even with an unloaded native thread. Positive deletion
records `revoked/dequeued`; false/error preserves `in_doubt/already_admitted`.
The native identity/version fence still applies. Repeated revoke is idempotent.
A known revoked item's later hook start records `in_doubt/revoked_started`, an
audit event and status error. This detects a failed fence; it cannot undo effects.
Offered/read informs keep their true receipt stage when revoked.
The final lab also found that the existing control admission burst bucket can
ACK-reject a terminal revoke receipt, leaving stale sender evidence even though
local dequeue and authority fencing succeeded. This remains a separate follow-up;
reliable remote revoke notification is not qualified by this run.
Mutual revoke can also close both relay route permits before terminal receipts
arrive. A relay route rejection for a locally revoked peer stops its receipt
retries, records `revoke_notification_undeliverable` and marks local notification
availability false without claiming remote delivery. Closed peers do not force
`offline`/`needs_rebind`, and their failed outbound flush does not gate another
peer's coauthor delivery or the second receipt flush. Transient failures and
relay denials for live peers retain their retries and do not revoke authority.

Control RPCs use short-lived connections, drain notifications until the response,
reject server requests and allow only initialization, metadata and queue methods.
The next call reconnects after server drop without rebinding or retrying a queue
submission. Native calls run without the daemon's state mutex, and hook binding
validation has a 750 ms budget. The client identifies as `peerturn`; pinned
Codex may update its global client-originator metadata during initialization.

## Fork responder qualification

The Go runner builds the argv below and passes framed question data through stdin:

```sh
codex exec -c 'sandbox_mode="read-only"' -c 'approval_policy="never"' \
  --skip-git-repo-check fork <exact-parent-thread>
```

The runner bounds deadline, output, concurrency, parent/conversation occupancy,
checks fresh authority before and after execution, reserves a durable budget,
validates a distinct child and whole final answer, then redacts configured known
secret patterns. Failed/cancelled/overflow runs discard partial output. It never
uses the live queue. It is deliberately not wired to product ask admission.

`NativeSandboxPreflight` separately runs standalone sandbox canaries. This is not
qualification of the actual `exec fork` permission pipeline, inherited integrations
or Unix sockets. Its OS-based engine label is not detected enforcement evidence.
Exact-path preflight and UDS canaries remain deferred to the ask milestone (M4
review finding); ask stays closed. Unit fixtures exercise the runner without a provider.

`fork_responder=false`, reason `protected_path_policy_failed`, is the stock
product result: read-only still exposes authority files and inherited integrations;
there is no qualified verifier/budget backend. The CLI returns typed
`responder_unavailable` (exit 6) without a paid run or live fallback. No signed
automatic responder reply is claimed. Broader read isolation, MCP/hosted tool
removal, effective model/effort/snapshot verification, cost accounting and macOS
qualification remain open. [The post-review Linux lab](../research/lab/results/m4-codex/fix-20261022/README.md)
pins final-binary coauthor/inform/native-dequeue evidence and its remote-receipt limitation.
