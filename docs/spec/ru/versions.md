# Политика версий агентов

Утверждено владельцем 25 октября 2026 года. Полный нормативный документ и
инвентарь контрактов: [английская спецификация](../versions.md).

1. Минимум Claude Code **2.1.306**, Codex CLI **0.163.0**. Верхней границы нет.
2. Все существующие функции доступны новым непроверенным версиям сразу, включая
   автоматический захват приглашений и уведомления на границе хода владельца.
   Статус — `newer_unverified`. «Спросить» остаётся отдельной закрытой функцией,
   доступной только проверенной версии с независимой квалификацией провайдера,
   ОС, изоляции и бюджета. Проверенность не создаёт права на сессию.
3. Новые версии автоматически проходят живую квалификацию в GitHub Actions по
   расписанию или ручному запуску **только из main**. Для неё предназначен
   отдельный ключ LiteLLM с малым бюджетом в repository secret. В PR ключ не
   передаётся, оплачиваемая квалификация не запускается.
4. После зелёной квалификации версия автоматически добавляется в проверенные
   и публикуется подписанный выпуск PeerTurn. При провале открывается issue на
   патч. Эти автоматизации утверждены, но не реализуются на шаге 1.
5. Сведения о сломанных версиях распространяются обновлением PeerTurn. Сетевого
   манифеста на этом этапе нет; старая офлайн-установка не узнаёт новое исключение.

Владелец принял остаточный риск: незаметное изменение смысла `origin.kind` или
идентификаторов ходов субагентов может представить чужую ссылку вставкой
владельца. Проверка структуры не доказывает семантику будущего агента. Нативные
проверки происхождения, точной сессии, процесса, сокета, эпохи и разрешений
сохраняются. `coauthor` — сильное доверие с обычными возможностями принимающего
агента; текст собеседника может повлиять и на последующие ходы владельца.

Центральный `internal/runtimepolicy` разбирает SemVer, вывод CLI и MCP-версии.
Состояния: `verified`, `newer_unverified`, `below_minimum`, `unknown`.
Build-метаданные не меняют порядок, но изменённая сборка не наследует проверку.
Prerelease базовой версии ниже минимума, prerelease будущей — непроверенная.
Изначально список проверенных содержит 2.1.306 / 0.163.0 с ограничениями исходных
лабораторных свидетельств; общий FAIL macOS live7 сохраняется.

`setup` показывает версию выбранного исполняемого файла; `status --json` и
`doctor` — фактического работающего агента, проверенность, контракты и доступные
возможности. Версия ниже минимума даёт `unsupported_version` до побочных
эффектов; неизвестная — `runtime_version_unknown`. Код выхода — 6.

Самопроверки при запуске/doctor ограничены структурными наблюдениями и чтением
метаданных: API Claude, версия/UUID, события и ответы helper; Codex initialize,
приватный сокет, loaded-list/thread-read и queue-list. Нет запросов модели,
пользовательских кадров или пробных queue-add/delete. Обычная явно запрошенная
привязка Claude отдельно использует существующий nonce: на сломанном агенте он
может дойти до модели; только нативное подтверждение доказывает привязку.

Провал контракта закрывает лишь зависимую возможность и возвращает
`runtime_contract_changed` с действием: обновить PeerTurn, возобновить ту же
сессию и повторить doctor/bind. Не наблюдавшийся хук — `not_observed`, а не успех.
Работа владельца и локальный отзыв не блокируются. После неоднозначной отправки
сохраняется `in_doubt` (выход 7), автоматической повторной отправки нет.
